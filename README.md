# Анализ эффективности доставки на данных Olist

**Учебный проект автора репозитория [@glebsm1337](https://github.com/glebsm1337).** Проект подготовлен при помощи ИИ-ассистента; исходные данные — открытый набор Olist, а результаты формируются при запуске скрипта.

## О проекте

Задача — понять, где возникают задержки в доставке заказов и как соблюдение обещанного срока связано с оценками покупателей. Это отдельный кейс про логистические операции: здесь нет воронки продаж, когортного удержания и A/B-теста из другого проекта.

Скрипт на Python:

- сопоставляет фактическую дату доставки с датой, обещанной покупателю;
- оценивает время на этапах «покупка → подтверждение оплаты», «подтверждение → передача перевозчику» и «передача → доставка»;
- сравнивает частоту опозданий по месяцу покупки и штату покупателя;
- сопоставляет среднюю оценку и долю однозвёздочных отзывов у заказов, доставленных в срок и с опозданием;
- сохраняет очищенные метрики, сводные таблицы и графики.

## Данные

Используется [Brazilian E-Commerce Public Dataset by Olist на Kaggle](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). Набор содержит связанные таблицы заказов, покупателей и отзывов. В проекте нужны три CSV-файла. Файлы данных не включены в репозиторий: скачайте архив с Kaggle и скопируйте их в `data/raw/`.

Подробности по источнику и структуре входных данных: [data/README.md](data/README.md).

## Как запустить

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
```

Активируйте виртуальное окружение и установите зависимости:

```bash
pip install -r requirements.txt
```

Распакуйте набор Olist в `data/raw/`, затем запустите:

```bash
python src/analyze_delivery.py
```

Порог для штата в региональной таблице по умолчанию — 100 заказов. Его можно изменить:

```bash
python src/analyze_delivery.py --min-state-orders 250
```

Можно задать другие папки с данными и результатами:

```bash
python src/analyze_delivery.py --data-dir путь/к/csv --output-dir путь/к/отчету
```

## Что получится

После запуска в папке `reports/` появятся:

- `summary.json` — основные метрики и счётчики качества данных;
- `tables/order_delivery_metrics.csv` — метрики на уровне заказа;
- `tables/overall_metrics.csv` — общая сводка;
- `tables/stage_duration_by_delivery_status.csv` — длительность этапов по статусу доставки;
- `tables/monthly_delivery_metrics.csv` — динамика по месяцу покупки;
- `tables/late_rate_by_customer_state.csv` — региональный срез;
- `tables/reviews_by_delivery_status.csv` — оценки клиентов по статусу доставки;
- `figures/` — графики по этапам, месяцам, регионам и оценкам.

## Методика и ограничения

- В расчёт попадают заказы со статусом `delivered`, с датами покупки, фактической и ожидаемой доставки.
- Опоздание — фактическая доставка позже ожидаемой даты. Доставка в саму ожидаемую дату считается своевременной.
- Заказы с повторным `order_id` сводятся к первой строке; число удалённых повторов записывается в `summary.json`.
- Некорректные и отсутствующие даты исключаются из соответствующих расчётов. Этапные интервалы с пропущенными датами не восстанавливаются.
- Если у одного заказа несколько отзывов, они агрегируются до одного среднего балла, чтобы не завысить вес заказа.
- Данные относятся к бразильскому маркетплейсу Olist и периоду, представленному в наборе; это не данные Ozon и не доказательство причинно-следственной связи между сроком доставки и оценкой.
